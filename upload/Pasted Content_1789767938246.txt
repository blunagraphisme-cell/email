# CAHIER DES CHARGES COMPLET

## MailOqui — Plateforme SaaS de gestion et d’automatisation des e-mails

**Nom du produit :** MailOqui
**Domaine :** mail.oquitogo.com
**Type :** SaaS B2B / plateforme de marketing et gestion d’e-mails
**Modèle :** White-label / service géré
**Infrastructure d’envoi :** Resend, intégrée côté serveur et invisible dans l’interface client
**Architecture :** Multi-tenant / Workspace
**Version :** V1

---

# 1. VISION DU PROJET

MailOqui est une plateforme SaaS permettant à des entreprises, organisations et professionnels de gérer leurs communications par e-mail depuis une interface centralisée.

La plateforme doit permettre notamment de :

* créer des campagnes e-mail ;
* gérer des contacts ;
* créer des listes et segments ;
* programmer des campagnes ;
* envoyer des campagnes ;
* créer des automatisations ;
* créer et gérer des modèles d’e-mails ;
* suivre les performances des campagnes ;
* consulter les statistiques d’envoi ;
* gérer les abonnements ;
* gérer les quotas ;
* gérer les domaines d’envoi ;
* recevoir et traiter les événements liés aux e-mails ;
* administrer plusieurs clients depuis une infrastructure centralisée.

MailOqui doit être présenté comme **le service utilisé par le client**.

Le fournisseur technique d’envoi d’e-mails utilisé en arrière-plan ne doit pas apparaître dans l'expérience utilisateur normale.

```text
├── Campaigns

├── Templates
```

Chaque donnée métier doit être rattachée à un :


18 décembre 2026

---

# 9. STATUTS D'ABONNEMENT

Les statuts possibles :

```text
EN_ATTENTE
ACTIF
EXPIRANT_BIENTOT
EXPIRE
SUSPENDU
ANNULE
```

## Règles

### ACTIF

Toutes les fonctions autorisées par le plan sont disponibles.

### EXPIRANT_BIENTOT

L'abonnement reste fonctionnel mais affiche les rappels de renouvellement.

### EXPIRE

Le système bloque :

* nouveaux envois ;
* campagnes programmées ;
* nouvelles exécutions d'automatisations.

Les anciennes statistiques restent accessibles selon la politique de conservation.

### SUSPENDU

Toutes les fonctions sensibles sont bloquées.

### ANNULE

Le Workspace ne peut plus utiliser les services concernés.

# 12. PROLONGATION

Le système doit distinguer :

### RENOUVELLEMENT

Créer une nouvelle période après la période actuelle.

### PROLONGATION

Ajouter une durée supplémentaire à la période existante.

Exemple :

Expiration actuelle :

18 décembre

Prolongation de 3 mois :

18 mars

Le calcul doit être effectué côté serveur.

# 14. SÉCURITÉ DES PAIEMENTS

MailOqui ne doit jamais stocker :

* numéro complet de carte ;
* CVV ;
* PIN ;
* mot de passe bancaire ;
* code OTP ;
* secret 3D Secure.

Les données bancaires doivent être traitées par un prestataire de paiement sécurisé.

MailOqui conserve uniquement les informations nécessaires :

* montant ;
* devise ;
* référence ;
* statut ;
* date ;
* identifiant fournisseur ;
* méthode ;
* éventuellement quatre derniers chiffres si fournis légalement par le prestataire.

5. domaine configuré ;

# 77. GESTION DES CONCURRENCES

Le système doit gérer deux campagnes lancées simultanément.

Campagne A :

# 92. CAS LIMITES OBLIGATOIRES

### Cas 1

### Cas 3

Le paiement est confirmé deux fois.

### Cas 4

Le webhook est reçu deux fois.

### Cas 5

Le propriétaire accepte une invitation expirée.

### Cas 6

Le propriétaire possède déjà un autre Workspace.

### Cas 7

Le domaine n'est pas vérifié.

### Cas 8

L'abonnement expire pendant une campagne.

### Cas 9

Le fournisseur d'envoi répond temporairement en erreur.

### Cas 10

Le fournisseur répond avec une erreur définitive.

### Cas 11

Un contact est désabonné puis réimporté.

### Cas 12

Un utilisateur tente de modifier une campagne d'un autre Workspace.

### Cas 13

Un token de renouvellement est utilisé deux fois.

### Cas 14

Un utilisateur manipule le prix dans le navigateur.

### Cas 15

Deux requêtes consomment simultanément le dernier quota disponible.
