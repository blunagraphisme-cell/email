     1→# CAHIER DES CHARGES COMPLET
     2→
     3→## MailOqui — Plateforme SaaS de gestion et d’automatisation des e-mails
     4→
     5→**Nom du produit :** MailOqui
     6→**Domaine :** mail.oquitogo.com
     7→**Type :** SaaS B2B / plateforme de marketing et gestion d’e-mails
     8→**Modèle :** White-label / service géré
     9→**Infrastructure d’envoi :** Resend, intégrée côté serveur et invisible dans l’interface client
    10→**Architecture :** Multi-tenant / Workspace
    11→**Version :** V1
    12→
    13→---
    14→
    15→# 1. VISION DU PROJET
    16→
    17→MailOqui est une plateforme SaaS permettant à des entreprises, organisations et professionnels de gérer leurs communications par e-mail depuis une interface centralisée.
    18→
    19→La plateforme doit permettre notamment de :
    20→
    21→* créer des campagnes e-mail ;
    22→* gérer des contacts ;
    23→* créer des listes et segments ;
    24→* programmer des campagnes ;
    25→* envoyer des campagnes ;
    26→* créer des automatisations ;
    27→* créer et gérer des modèles d’e-mails ;
    28→* suivre les performances des campagnes ;
    29→* consulter les statistiques d’envoi ;
    30→* gérer les abonnements ;
    31→* gérer les quotas ;
    32→* gérer les domaines d’envoi ;
    33→* recevoir et traiter les événements liés aux e-mails ;
    34→* administrer plusieurs clients depuis une infrastructure centralisée.
    35→
    36→MailOqui doit être présenté comme **le service utilisé par le client**.
    37→
    38→Le fournisseur technique d’envoi d’e-mails utilisé en arrière-plan ne doit pas apparaître dans l'expérience utilisateur normale.
    39→

    44→## 2.1 White-label

    46→L'utilisateur final doit voir :
    47→
    48→**MailOqui**
    49→

    53→
    54→* le nom du fournisseur technique ;
    55→* son logo ;
    56→* son tableau de bord ;
    57→* ses URLs ;
    58→* ses clés API ;
    59→* ses identifiants ;
    60→* ses informations techniques internes.
    61→
    62→Cependant, les obligations légales applicables concernant les sous-traitants, la confidentialité et le traitement des données doivent être respectées dans les documents juridiques de MailOqui.

    91→* suspendre un compte ;
    92→* réactiver un compte ;

    94→* gérer les paramètres globaux.

    96→Il possède les droits les plus élevés.

   158→* gérer les automatisations ;

   166→# 6. WORKSPACE
   167→
   168→Chaque client possède un Workspace indépendant.
   169→
   170→Exemple :
   171→
   172→```text
   173→Workspace
   174→│
   175→├── Developer
   176→├── Owner
   177→├── Subscription
   178→├── Campaigns
   179→├── Contacts
   180→├── Templates
   181→├── Automations
   182→├── Email Events
   183→├── Analytics
   184→├── Domain Configuration
   185→└── Audit Logs
   186→```
   187→
   188→Chaque donnée métier doit être rattachée à un :
   189→
   190→```text
   191→workspace_id
   192→```
   193→
   194→Aucune donnée d'un client ne doit être accessible depuis le Workspace d'un autre client.

   268→# 9. STATUTS D'ABONNEMENT
   269→
   270→Les statuts possibles :
   271→
   272→```text
   273→EN_ATTENTE
   274→ACTIF
   275→EXPIRANT_BIENTOT
   276→EXPIRE
   277→SUSPENDU
   278→ANNULE
   279→```
   280→
   281→## Règles
   282→
   283→### ACTIF
   284→
   285→Toutes les fonctions autorisées par le plan sont disponibles.
   286→
   287→### EXPIRANT_BIENTOT
   288→
   289→L'abonnement reste fonctionnel mais affiche les rappels de renouvellement.
   290→
   291→### EXPIRE
   292→
   293→Le système bloque :
   294→
   295→* nouveaux envois ;
   296→* campagnes programmées ;
   297→* nouvelles exécutions d'automatisations.
   298→
   299→Les anciennes statistiques restent accessibles selon la politique de conservation.
   300→
   301→### SUSPENDU
   302→
   303→Toutes les fonctions sensibles sont bloquées.
   304→
   305→### ANNULE
   306→
   307→Le Workspace ne peut plus utiliser les services concernés.
   308→

   327→# 11. RENOUVELLEMENT
   328→
   329→Le Developer peut générer un lien de renouvellement pour le propriétaire.
   330→
   331→Le lien doit être :
   332→
   333→* unique ;
   334→* temporaire ;
   335→* sécurisé ;
   336→* lié au Workspace ;
   337→* lié à l'abonnement ;
   338→* non modifiable côté client ;
   339→* inutilisable après expiration ;
   340→* inutilisable après consommation.
   341→
   342→Exemple :
   343→
   344→```text
   345→mail.oquitogo.com/renew/xxxxxxxx
   346→```
   347→
   348→Le token réel doit être aléatoire et stocké sous forme de hash.
   349→
   350→---
   351→
   352→# 12. PROLONGATION
   353→
   354→Le système doit distinguer :
   355→
   356→### RENOUVELLEMENT
   357→
   358→Créer une nouvelle période après la période actuelle.
   359→
   360→### PROLONGATION
   361→
   362→Ajouter une durée supplémentaire à la période existante.
   363→
   364→Exemple :
   365→
   366→Expiration actuelle :
   367→
   368→18 décembre
   369→
   370→Prolongation de 3 mois :
   371→
   372→18 mars
   373→
   374→Le calcul doit être effectué côté serveur.

   394→# 14. SÉCURITÉ DES PAIEMENTS
   395→
   396→MailOqui ne doit jamais stocker :
   397→
   398→* numéro complet de carte ;
   399→* CVV ;
   400→* PIN ;
   401→* mot de passe bancaire ;
   402→* code OTP ;
   403→* secret 3D Secure.
   404→
   405→Les données bancaires doivent être traitées par un prestataire de paiement sécurisé.
   406→
   407→MailOqui conserve uniquement les informations nécessaires :
   408→
   409→* montant ;
   410→* devise ;
   411→* référence ;
   412→* statut ;
   413→* date ;
   414→* identifiant fournisseur ;
   415→* méthode ;
   416→* éventuellement quatre derniers chiffres si fournis légalement par le prestataire.
   417→
