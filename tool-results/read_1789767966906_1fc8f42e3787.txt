     4→     4→
     5→     5→**Nom du produit :** MailOqui
     6→     6→**Domaine :** mail.oquitogo.com
     7→     7→**Type :** SaaS B2B / plateforme de marketing et gestion d’e-mails
     8→     8→**Modèle :** White-label / service géré
     9→     9→**Infrastructure d’envoi :** Resend, intégrée côté serveur et invisible dans l’interface client

    14→    14→
    15→    15→# 1. VISION DU PROJET
    16→    16→
    17→    17→MailOqui est une plateforme SaaS permettant à des entreprises, organisations et professionnels de gérer leurs communications par e-mail depuis une interface centralisée.
    18→    18→
    19→    19→La plateforme doit permettre notamment de :
    20→    20→
    21→    21→* créer des campagnes e-mail ;
    22→    22→* gérer des contacts ;
    23→    23→* créer des listes et segments ;
    24→    24→* programmer des campagnes ;
    25→    25→* envoyer des campagnes ;
    26→    26→* créer des automatisations ;
    27→    27→* créer et gérer des modèles d’e-mails ;
    28→    28→* suivre les performances des campagnes ;
    29→    29→* consulter les statistiques d’envoi ;
    30→    30→* gérer les abonnements ;
    31→    31→* gérer les quotas ;
    32→    32→* gérer les domaines d’envoi ;
    33→    33→* recevoir et traiter les événements liés aux e-mails ;
    34→    34→* administrer plusieurs clients depuis une infrastructure centralisée.
    35→    35→
    36→    36→MailOqui doit être présenté comme **le service utilisé par le client**.
    37→    37→
    38→    38→Le fournisseur technique d’envoi d’e-mails utilisé en arrière-plan ne doit pas apparaître dans l'expérience utilisateur normale.
    39→    39→

   170→   170→Exemple :
   171→   171→
   172→   172→```text
   173→   173→Workspace
   174→   174→│
   175→   175→├── Developer
   176→   176→├── Owner
   177→   177→├── Subscription
   178→   178→├── Campaigns
   179→   179→├── Contacts
   180→   180→├── Templates
   181→   181→├── Automations
   182→   182→├── Email Events
   183→   183→├── Analytics
   184→   184→├── Domain Configuration
   185→   185→└── Audit Logs
   186→   186→```
   187→   187→
   188→   188→Chaque donnée métier doit être rattachée à un :
   189→   189→
   190→   190→```text
   191→   191→workspace_id
   192→   192→```
   193→   193→
   194→   194→Aucune donnée d'un client ne doit être accessible depuis le Workspace d'un autre client.

   268→   268→# 9. STATUTS D'ABONNEMENT
   269→   269→
   270→   270→Les statuts possibles :
   271→   271→
   272→   272→```text
   273→   273→EN_ATTENTE
   274→   274→ACTIF
   275→   275→EXPIRANT_BIENTOT
   276→   276→EXPIRE
   277→   277→SUSPENDU
   278→   278→ANNULE
   279→   279→```
   280→   280→
   281→   281→## Règles
   282→   282→
   283→   283→### ACTIF
   284→   284→
   285→   285→Toutes les fonctions autorisées par le plan sont disponibles.
   286→   286→
   287→   287→### EXPIRANT_BIENTOT
   288→   288→
   289→   289→L'abonnement reste fonctionnel mais affiche les rappels de renouvellement.
   290→   290→
   291→   291→### EXPIRE
   292→   292→
   293→   293→Le système bloque :
   294→   294→
   295→   295→* nouveaux envois ;
   296→   296→* campagnes programmées ;
   297→   297→* nouvelles exécutions d'automatisations.
   298→   298→
   299→   299→Les anciennes statistiques restent accessibles selon la politique de conservation.
   300→   300→
   301→   301→### SUSPENDU
   302→   302→
   303→   303→Toutes les fonctions sensibles sont bloquées.
   304→   304→
   305→   305→### ANNULE
   306→   306→
   307→   307→Le Workspace ne peut plus utiliser les services concernés.
   308→   308→
   309→   309→---
   310→   310→
   311→   311→# 10. RAPPELS D'EXPIRATION
   312→   312→

   320→   320→
   321→   321→Le système doit éviter les doublons.

   327→   327→# 11. RENOUVELLEMENT
   328→   328→
   329→   329→Le Developer peut générer un lien de renouvellement pour le propriétaire.
   330→   330→
   331→   331→Le lien doit être :
   332→   332→
   333→   333→* unique ;
   334→   334→* temporaire ;
   335→   335→* sécurisé ;
   336→   336→* lié au Workspace ;
   337→   337→* lié à l'abonnement ;
   338→   338→* non modifiable côté client ;
   339→   339→* inutilisable après expiration ;
   340→   340→* inutilisable après consommation.
   341→   341→
   342→   342→Exemple :
   343→   343→
   344→   344→```text
   345→   345→mail.oquitogo.com/renew/xxxxxxxx
   346→   346→```
   347→   347→
   348→   348→Le token réel doit être aléatoire et stocké sous forme de hash.
   349→   349→

   351→   351→
   352→   352→# 12. PROLONGATION
   353→   353→
   354→   354→Le système doit distinguer :
   355→   355→

   359→   359→
   360→   360→### PROLONGATION
   361→   361→
   362→   362→Ajouter une durée supplémentaire à la période existante.
   363→   363→
   364→   364→Exemple :
   365→   365→
   366→   366→Expiration actuelle :
   367→   367→
   368→   368→18 décembre
   369→   369→
   370→   370→Prolongation de 3 mois :
   371→   371→
   372→   372→18 mars
   373→   373→
   374→   374→Le calcul doit être effectué côté serveur.

   394→   394→# 14. SÉCURITÉ DES PAIEMENTS
   395→   395→
   396→   396→MailOqui ne doit jamais stocker :
   397→   397→
   398→   398→* numéro complet de carte ;
   399→   399→* CVV ;
   400→   400→* PIN ;
   401→   401→* mot de passe bancaire ;
   402→   402→* code OTP ;
   403→   403→* secret 3D Secure.
   404→   404→
   405→   405→Les données bancaires doivent être traitées par un prestataire de paiement sécurisé.
   406→   406→
   407→   407→MailOqui conserve uniquement les informations nécessaires :
   408→   408→
   409→   409→* montant ;
   410→   410→* devise ;
   411→   411→* référence ;
   412→   412→* statut ;
   413→   413→* date ;
   414→   414→* identifiant fournisseur ;
   415→   415→* méthode ;
   416→   416→* éventuellement quatre derniers chiffres si fournis légalement par le prestataire.
   417→   417→
